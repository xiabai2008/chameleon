# Chameleon 🦎 — 实战级 AI Agent 爬虫工具开发方案

> **目标**：构建一个面向真实世界反爬、动态渲染、异常容错的爬虫工具，同时提供 Agent 可调用的高易用接口（MCP Server + REST API + CLI）。核心理念：**分层对抗，自适应降级，Agent 友好输出**。

---

## 一、项目定位与核心价值

| 维度 | 说明 |
|------|------|
| **目标用户** | AI Agent、RAG 流水线、自动化分析脚本、数据采集团队 |
| **核心目标** | 把"拿到网页内容"这件事从"能跑"变成"稳定、可解释、可回退、可扩展" |
| **交付形态** | 可独立部署的 Python 服务：MCP Server + REST API + CLI + 调度后台 |
| **与 Firecrawl/Crawl4AI 的差异** | 自主可控、可本地部署、针对中文/国内站点和反爬场景深度优化 |
| **开源策略** | 核心引擎开源 (MIT/Apache 2.0)，可选对接第三方付费服务 |

## 二、实战场景全景图（28 类场景，必须覆盖）

基于 2025-2026 年最新实践调研，现代爬虫需要应对以下场景：

### 2.1 反爬检测层（12 类）

| # | 场景 | 具体表现 | 应对策略 |
|---|------|----------|----------|
| 1 | **IP 频率限制** | 单 IP 短时间高并发 → 429 / 封 IP | 代理池 + 自适应 QPS 控制 |
| 2 | **IP 地域检测** | 非目标地区 IP 触发验证码 | 按目标站地理区域选择代理 |
| 3 | **User-Agent 检测** | 默认 UA / 空 UA 直接拒绝 | UA 池轮换，维护最新浏览器 UA 列表 |
| 4 | **请求头完整性** | 缺少 Referer / Accept-Language 等头 | 完整请求头模拟，自动补全 |
| 5 | **Cookie / Session 追踪** | 无 Cookie 或同一 Cookie 高频请求 | Session 池管理，Cookie 自动维护 |
| 6 | **浏览器指纹检测** | Canvas/WebGL/Font/Audio 指纹 | Playwright + `playwright-stealth` |
| 7 | **TLS 指纹（JA3/JA4）** | Python requests 的 TLS 特征暴露 | 使用 `curl_cffi` / `tls_client` 伪装浏览器 TLS |
| 8 | **验证码（CAPTCHA）** | 图片验证码 / reCAPTCHA / 滑块 | 检测触发阈值 → 换代理 → 打码服务 API |
| 9 | **行为分析** | 鼠标轨迹/滚动速度/点击间隔异常 | Playwright 模拟人类操作轨迹 |
| 10 | **蜜罐陷阱（Honeypot）** | `display:none` 链接、隐藏表单 | 前端可见性检测，只访问视觉元素 |
| 11 | **JavaScript 挑战** | `navigator.webdriver` / Cloudflare 5秒盾 | 真实浏览器渲染，注入反检测脚本 |
| 12 | **WAF / CDN 层拦截** | Cloudflare / Akamai / DataDome | 住宅代理 + 浏览器指纹 + 慢速策略 |

## 三、技术栈选型

| 层级 | 推荐技术 | 备选 / 说明 |
|------|----------|-------------|
| **编程语言** | Python 3.11+ | 生态最成熟，Scrapy/Playwright/Crawl4AI 均为 Python 优先 |
| **HTTP 客户端** | `httpx` (async) + `curl_cffi` | httpx 支持 HTTP/2 & async；curl_cffi 伪装浏览器 TLS/JA3 指纹 |
| **HTML 解析** | `selectolax` + `BeautifulSoup4` + `lxml` | selectolax 速度最快(C++引擎)，BS4 容错最好 |
| **浏览器自动化** | `Playwright` (Python) + `playwright-stealth` | 现代 API，跨浏览器，反检测能力远强于 Selenium |
| **Markdown 转换** | `markdownify` / `html2text` | 将 HTML 转为 LLM 友好的 Markdown |
| **结构化提取** | CSS + XPath + `Pydantic v2` | 多策略提取，Pydantic 做数据模型校验 |
| **MCP Server** | `mcp` Python SDK (FastMCP) | 官方 Python SDK，支持 stdio + Streamable HTTP |
| **REST API** | `FastAPI` | async 原生、自动生成 OpenAPI 文档 |
| **任务队列** | `Celery` + `Redis` / `arq` | 异步任务、定时调度、结果回调 |
| **代理池** | Redis + 自研调度器 | 支持住宅/数据中心代理，健康检查 + 评分淘汰 |
| **验证码处理** | `ddddocr` + CapSolver/2Captcha API | ddddocr 处理简单验证码，第三方处理复杂验证码 |
| **缓存** | `Redis` | 高速 KV 存储，适合缓存和代理池 |
| **日志监控** | `structlog` + `Prometheus` | 结构化日志 + 指标采集 |
| **容器化** | `Docker` + `Docker Compose` | 一键部署所有服务 |

### 不选的其他方案

| 不选 | 原因 |
|------|------|
| Scrapy（作为主框架） | 对 JS 渲染支持弱，启动重，不适合 Agent 即时调用；但可参考其中间件设计 |
| Selenium | API 陈旧，反检测弱，已被 Playwright 取代 |
| Puppeteer (Node) | 跨语言调用增加复杂度，Python 生态更统一 |
| Firecrawl（作为唯一依赖） | 闭源/付费 API，不可控；但可作为参考设计和可选后端 |

### 关键设计原则

1. **三层降级策略**：Light HTTP → Headless Browser → API Reverse Engineering
2. **6 级自动升级**：从裸请求到行为模拟，按需逐级升级（详见第七节）
3. **自适应 QPS**：根据响应延迟和 429 频率自动调整速率
4. **响应内容校验**：不只看 HTTP Status Code，还检测实际内容是否异常
5. **Agent 友好输出**：默认输出 Markdown，支持 Pydantic Schema 提取 JSON

## 五、核心模块详细设计

### 5.1 智能路由器 (Smart Router)

核心职责：根据目标 URL 的特征，自动选择最优采集策略。

**决策逻辑**：
1. 先尝试 HTTP 模式（最快、最省资源）
2. 如果检测到 JS 渲染标记（页面缺少关键内容、存在 SPA 特征）→ 升级到 Browser 模式
3. 如果发现内部 API 端点 → 切换到 API 直调模式
4. 支持手动指定模式 (`force_browser=true`)

**自动升级触发条件**：
- HTTP 返回内容过短（<500 字符）→ 可能是 JS 渲染 → 自动重试 Browser
- HTTP 返回 403/429 → 触发代理切换 + 重试
- HTTP 返回 200 但内容为反爬页面 → 内容检测 + 策略升级

### 5.2 反爬策略引擎 (Anti-Detection Engine)

模块化设计，可按需组合：

| 子模块 | 功能要点 |
|--------|----------|
| **ProxyManager** | 代理池维护(Redis)、健康检查、评分淘汰、地理定位选择 |
| **IdentityFaker** | UA 池(200+真实浏览器)、完整请求头生成、TLS 指纹模拟(curl_cffi) |
| **BehaviorSimulator** | 请求间隔随机化(2-10s 正态分布)、模拟人类浏览(滚动/鼠标/停留)、Session 连续性 |
| **CaptchaRouter** | 自动检测验证码类型 → 简单:ddddocr / 复杂:CapSolver / 滑块:图像识别+轨迹 |
| **StealthPlugin** | playwright-stealth 隐藏 navigator.webdriver、指纹随机化(Canvas/WebGL/Font) |
| **HoneypotFilter** | 过滤 `display:none` / `visibility:hidden` 元素，只访问视觉可见链接 |

### 5.3 处理管线 (Processing Pipeline)

```
原始 HTML → 清洗(去script/style/导航/广告) → 主内容提取(readability)
    → Markdown 转换 → 结构化提取(CSS/XPath/LLM) → Pydantic 校验 → 输出
```

**关键特性**：
- **BM25 内容过滤**：根据用户查询过滤相关内容（参考 Crawl4AI）
- **去重**：URL 去重 + 内容指纹去重 (simhash)
- **增量采集**：ETag / Last-Modified 检测，只抓取变更内容

### 5.4 深度爬取引擎 (Deep Crawler)

- **爬取策略**：BFS（广度优先）、DFS（深度优先）、Adaptive（信息觅食，参考 Crawl4AI）
- **URL 过滤**：同域名过滤、路径模式匹配、黑名单排除
- **并发控制**：每个域名独立限速，全局并发上限
- **断点续爬**：任务持久化到 Redis，支持中断后恢复
- **robots.txt**：自动解析并遵循规则

## 六、Agent 接口设计

### 6.1 MCP Server（主要推荐）

实现 Model Context Protocol，让 Agent 自动发现和调用爬虫工具。

**设计原则**：
- MCP-native：Agent 通过协议自动发现所有工具及其参数 Schema，零胶水代码
- 支持 stdio 和 Streamable HTTP 两种传输模式
- 每个工具返回结构化、token-efficient 的输出

**暴露的 12 个核心工具**：

| 工具名 | 功能 | 关键参数 |
|--------|------|----------|
| `scrape_url` | 采集单个 URL 并转为 Markdown/JSON | url, format(markdown\|json\|html), wait_for, js_render(bool) |
| `crawl_site` | 深度爬取整个网站 | url, max_pages, max_depth, strategy(bfs\|dfs\|adaptive), url_filter |
| `map_site` | 快速发现网站所有 URL（不抓取内容） | url, sitemap_only(bool) |
| `extract_data` | 基于 Schema 从网页提取结构化数据 | url, schema(JSON Schema), strategy(css\|xpath\|llm\|auto) |
| `search_web` | 搜索互联网并返回结果页面的 Markdown | query, max_results, language |
| `batch_scrape` | 批量采集多个 URL | urls(list), format, concurrency |
| `get_screenshot` | 获取网页截图 | url, full_page(bool), selector |
| `get_network_log` | 获取页面网络请求日志（用于 API 发现） | url, filter_type(xhr\|fetch\|all) |
| `diagnose_site` | 诊断网站反爬能力和推荐策略 | url |
| `check_proxy` | 检测代理 IP 的可用性和信息 | proxy_url |
| `get_job_status` | 查询异步任务状态 | job_id |
| `get_robots_txt` | 获取网站的 robots.txt 规则 | url |

**MCP 工具 Schema 示例**（scrape_url）：

```json
{
  "name": "scrape_url",
  "description": "Fetch a single web page and return clean markdown or structured data. Use this when the user asks about a specific URL.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "url": { "type": "string", "format": "uri" },
      "mode": { "type": "string", "enum": ["auto", "static", "dynamic"], "default": "auto" },
      "output_format": { "type": "string", "enum": ["markdown", "html", "json"], "default": "markdown" },
      "schema": { "type": "object", "description": "JSON Schema for structured extraction" },
      "extract_prompt": { "type": "string", "description": "Natural language description of what to extract" },
      "wait_for": { "type": "string", "description": "CSS selector to wait for" },
      "proxy_region": { "type": "string", "description": "Proxy country code e.g. cn, us" },
      "stealth_level": { "type": "string", "enum": ["low", "medium", "high"], "default": "medium" }
    },
    "required": ["url"]
  }
}
```

### 6.2 REST API（辅助接口）

基于 FastAPI 构建，提供 HTTP 接口供非 MCP 客户端调用。端点与 MCP 工具一一对应：

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/v1/scrape` | POST | 单页抓取（同步） |
| `/api/v1/crawl` | POST | 多页/站点抓取（异步，返回 job_id） |
| `/api/v1/map` | POST | URL 发现 |
| `/api/v1/extract` | POST | 结构化提取 |
| `/api/v1/search` | POST | 搜索 + 抓取 |
| `/api/v1/batch` | POST | 批量抓取 |
| `/api/v1/screenshot` | POST | 截图 |
| `/api/v1/jobs/{job_id}` | GET | 查询任务状态 |
| `/api/v1/jobs/{job_id}/results` | GET | 获取任务结果 |

### 6.3 CLI 命令行工具

Agent 也可通过 exec_command 直接调用：

```bash
# 基础抓取
chameleon scrape https://example.com -o markdown

# 深度爬取
chameleon crawl https://example.com --max-pages 50 --strategy adaptive

# 结构化提取
chameleon extract https://example.com --schema product.json

# 搜索
chameleon search "Python web scraping" --max-results 10

# 站点地图
chameleon map https://example.com

# 代理检测
chameleon proxy check http://proxy:8080
```

退出码：0=成功, 1=采集失败, 2=反爬拦截, 3=验证码未解决

### 6.4 统一输出格式

所有接口返回统一数据结构，对 Agent 友好：

```json
{
  "status": "success | error | captcha_required | rate_limited",
  "url": "https://...",
  "title": "Page Title",
  "content": {
    "markdown": "# Clean Markdown Content...",
    "html": "<cleaned html>",
    "raw_html": "<original html>"
  },
  "extracted": { },
  "metadata": {
    "status_code": 200,
    "response_time_ms": 450,
    "content_length": 15234,
    "language": "zh-CN",
    "engine": "browser",
    "proxy_used": "1.2.3.4:8080",
    "retries": 1,
    "stealth_level": "medium",
    "timestamp": "2026-08-09T10:00:00Z"
  },
  "links": ["https://..."],
  "images": ["https://..."],
  "error": null
}
```

**设计理念**：
- Markdown 为默认输出（LLM 最友好，token 效率最高）
- metadata 中记录采集过程信息，方便 Agent 判断结果可信度
- status 字段让 Agent 能自主决策下一步动作（重试/换策略/上报）

## 七、反爬自动升级策略（核心创新）

从最轻量策略开始，按需逐级升级：

```
Level 0: 裸请求 (HTTPX, 无伪装)
  → 失败/内容异常 → Level 1

Level 1: HTTP + 自定义 UA + 基础请求头
  → 失败 → Level 2

Level 2: HTTP + UA轮换 + 代理 + 完整请求头
  → 失败 → Level 3

Level 3: HTTP + TLS指纹模拟(curl_cffi) + 住宅代理
  → 失败 → Level 4

Level 4: Browser(Playwright) + stealth补丁 + 代理
  → 失败 → Level 5

Level 5: Browser + 指纹随机化 + 行为模拟 + 住宅代理
  → 失败 → Level 6

Level 6: 触发验证码 → 验证码解决 + 重试
  → 失败 → 标记为不可达，通知 Agent
```

每次升级记录到日志，Agent 可通过 `metadata.engine` 和 `metadata.retries` 了解采集过程。

### 9.5 智能路由器（简化版）

```python
class SmartRouter:
    async def fetch(self, url: str, force_browser: bool = False) -> FetchResult:
        if force_browser:
            return await self.browser_engine.fetch(url)

        # Level 0-1: 先尝试 HTTP
        result = await self.http_engine.fetch(url)
        if self._is_valid_content(result):
            return result

        # Level 2-3: HTTP 失败，升级到 TLS 伪装 + 代理
        result = await self.http_engine.fetch_with_stealth(url)
        if self._is_valid_content(result):
            return result

        # Level 4-5: HTTP 都失败，升级到浏览器
        result = await self.browser_engine.fetch(url)
        return result

    def _is_valid_content(self, result) -> bool:
        if result.status_code in (403, 429):
            return False
        if len(result.content) < 500:
            return False
        # 检测反爬关键词
        anti_bot_markers = ["captcha", "access denied", "请输入验证码"]
        if any(m in result.content.lower() for m in anti_bot_markers):
            return False
        return True
```

## 十六、附录：Crawl4AI 架构深度解析与 MCP Server 生产级设计模式

> 本节基于对 Crawl4AI v0.9.x 源码、官方文档、社区架构分析以及 MCP 协议规范与实践的深入调研，提炼出可直接指导本方案开发的关键设计模式。

### 16.1 Crawl4AI 架构深度解析

Crawl4AI 是目前 GitHub 上最成熟的 LLM 友好开源爬虫框架（Apache 2.0，91k+ Stars），其架构设计对本方案有重要参考价值。

#### 16.1.1 分层架构全景

Crawl4AI 采用清晰的四层架构，层与层之间通过接口解耦：

```
┌──────────────────────────────────────────────────────────────┐
│                    用户 / Agent API 层                        │
│   AsyncWebCrawler.arun()  │  arun_many()  │  Docker REST API  │
├──────────────────────────────────────────────────────────────┤
│                    编排与配置层                               │
│   BrowserConfig  │  CrawlerRunConfig  │  CacheMode            │
├──────────────────────────────────────────────────────────────┤
│                    浏览器管理层                               │
│   Playwright 管理  │  Session 管理  │  代理注入  │  钩子系统   │
├──────────────────────────────────────────────────────────────┤
│                    内容处理管线                               │
│   HTML 清洗 → Markdown 生成 → 内容过滤 → 提取策略 → 输出     │
└──────────────────────────────────────────────────────────────┘
```

| 层 | 职责 | 对应核心类/模块 |
|------|------|---------------------|
| 调度层 | 管理并发、Session、任务队列 | `AsyncWebCrawler`, `BrowserManager` |
| 执行层 | 渲染页面、执行 JS、拦截网络 | `CrawlerWorker`, Playwright/Chromium |
| 处理层 | HTML 清洗、Markdown 生成、内容过滤 | `DefaultMarkdownGenerator`, `FilterChain` |
| 提取层 | 结构/半结构化数据提取 | `ExtractionStrategy` 及子类 |
| 输出层 | 输出 Markdown/JSON/截图/链接 | `CrawlResult` |

#### 16.1.2 核心组件详解

**AsyncWebCrawler**：顶层入口，异步上下文管理器。
- 使用 `async with` 管理浏览器实例生命周期
- 核心方法：`arun(url)` 单页采集，`arun_many(urls)` 批量并发
- 默认启用缓存，相同 URL 二次请求直接命中
- 统一异常处理，错误不会中断批量任务

**BrowserConfig**：浏览器实例的启动配置。
- `browser_type`: chromium / firefox / webkit
- `headless`: 无头模式控制
- `viewport_width/height`: 视口尺寸（影响指纹一致性）
- `proxy_config`: 代理透明注入
- `extra_args`: Chrome 启动参数（如 `--disable-blink-features=AutomationControlled`）

**CrawlerRunConfig**：单次采集行为的运行时配置。
- `extraction_strategy`: 提取策略实例
- `markdown_generator`: Markdown 生成器 + 内容过滤器
- `cache_mode`: ENABLED / BYPASS / WRITE_ONLY / READ_ONLY
- `wait_for`: CSS 选择器等待条件
- `js_code` / `js_only`: JavaScript 执行控制
- `session_id`: 跨页面会话保持
- `stream`: 流式返回模式
- `magic`: 自动参数推断（自动等待 DOM、自动检测渲染需求）

#### 16.1.3 内容处理管线（数据流）

这是本方案需要重点借鉴的设计：

```
Raw HTML
  │
  ▼
WebScrapingStrategy.cleanup()     ← 去 script/style/nav/footer
  │
  ▼
DefaultMarkdownGenerator          ← HTML → Markdown 转换
  │  ├─ PruningContentFilter      ← 按阈值剪枝低信息密度节点
  │  ├─ BM25ContentFilter         ← 按用户查询相关性过滤段落
  │  ├─ LLMContentFilter          ← 用 LLM 筛相关段落（最慢）
  │  └─ None (无过滤)
  │
  ▼
Filtered Markdown / Fit Markdown  ← 精简 Markdown，适配上下文窗口
  │
  ▼
ExtractionStrategy                ← 提取结构化数据
  ├─ JsonCssExtractionStrategy    ← CSS 选择器 + JSON Schema
  ├─ JsonXPathExtractionStrategy  ← XPath 选择器 + JSON Schema
  ├─ LLMExtractionStrategy        ← LLM 语义提取（BYO-LLM via LiteLLM）
  └─ RegexExtractionStrategy      ← 正则表达式提取
  │
  ▼
CrawlResult                       ← 最终输出
  ├─ markdown (raw & fit)
  ├─ extracted_content (JSON)
  ├─ links (internal & external)
  ├─ media (images/videos/audio)
  └─ metadata
```

**关键设计洞察**：
- **Fit Markdown**：将 Markdown 按 token 预算裁剪，适配 LLM 上下文窗口。这是 Agent 场景的核心功能
- **先过滤再提取**：先用低成本的 `PruningContentFilter` 或 `BM25ContentFilter` 缩减内容，再送 LLM 提取，大幅降低 token 成本
- **一次 LLM 生成 Schema，后续 CPU 执行**：用 LLM 分析 1-2 个样本页面生成 `JsonCssExtractionStrategy` 的 Schema，然后同类型页面全部用 CSS 提取，不再消耗 LLM token

#### 16.1.4 提取策略对比

| 策略 | 速度 | 成本 | 精确度 | 适合场景 |
|------|------|------|--------|----------|
| `JsonCssExtractionStrategy` | 极快（纯 CPU） | 零 | 中等（依赖页面结构稳定） | 同构页面批量提取 |
| `JsonXPathExtractionStrategy` | 极快 | 零 | 中等 | XML/非标准结构 |
| `LLMExtractionStrategy` | 慢（依赖 LLM 延迟） | 高（按 token 计费） | 高（语义理解） | 异构页面、复杂语义提取 |
| `RegexExtractionStrategy` | 极快 | 零 | 低 | 固定格式文本提取 |

**Hybrid 模式（本方案推荐）**：先用 LLM 分析 1-2 个样本页面生成 CSS/XPath Schema → 后续页面全部用无 LLM 策略提取 → 监控提取结果质量，发现漂移时触发 LLM 重新生成 Schema。

#### 16.1.5 Session 管理与多页交互

```python
# Session 跨页面保持登录态 / Cookie
async with AsyncWebCrawler() as crawler:
    # 第 1 步：登录
    result1 = await crawler.arun(
        url="https://example.com/login",
        config=CrawlerRunConfig(
            js_code="document.querySelector('#username').value='admin';
                     document.querySelector('#password').value='pass';
                     document.querySelector('#login-btn').click();",
            session_id="my_session"
        )
    )

    # 第 2 步：访问需要登录的页面（自动继承 Cookie）
    result2 = await crawler.arun(
        url="https://example.com/dashboard",
        config=CrawlerRunConfig(session_id="my_session")
    )
```

**启示**：Session 管理必须是一等公民。支持登录态保持、分页遍历、表单提交的连续操作。

#### 16.1.6 钩子系统（Hooks）

Crawl4AI 支持在爬取生命周期中注入自定义逻辑：

- `on_browser_created`: 浏览器实例创建后（注入 stealth 脚本的好时机）
- `on_page_context_created`: 页面上下文创建后
- `before_goto`: 导航前（修改 URL、注入 headers）
- `after_goto`: 页面加载后（执行自定义 JS）
- `on_user_agent_updated`: UA 变更后

**本方案应借鉴**：设计类似的 Hook 机制，让用户可以注入自定义的反检测逻辑。

#### 16.1.7 Docker 部署与 Webhook

Crawl4AI v0.7.6+ 提供了完整的 Docker Job Queue API + Webhook 机制：

- 提交爬取/LLM 提取任务 → 返回 `task_id` → Webhook 回调通知完成
- 消除了轮询需求，适合异步 Agent 工作流
- 任务类型：`crawl`（普通采集）和 `llm_extraction`（LLM 语义提取）

**本方案借鉴**：REST API 的异步任务模式应支持 Webhook 回调，而非仅靠轮询。

#### 16.1.8 对本方案设计的启示汇总

1. **缓存分层**：URL 级缓存 → Markdown 级缓存 → 提取结果级缓存，逐级复用
2. **Magic Mode**：自动推断页面是否需要 JS 渲染、等待时间等参数
3. **Schema 生成复用**：LLM 生成一次 Schema → CSS 批量提取，大幅降低 API 成本
4. **Fit Markdown**：按 token 预算裁剪输出，Agent 场景的核心需求
5. **Stream 模式**：支持流式返回，Agent 可以边收边处理
6. **策略模式优于枚举**：通过 `ExtractionStrategy` 抽象基类，可不断新增提取方式，不改动核心代码
7. **配置对象化**：`CrawlerRunConfig` + `BrowserConfig` 将"任务参数"与"浏览器参数"解耦，便于组合复用
8. **LLM 只做最后一公里**：先用清洗+过滤得到高质量文本，再用 LLM 做语义提取，降低成本

### 16.2 MCP Server 生产级设计模式

基于对 MCP 协议规范（2025-06-18 版）、社区实践和已有爬虫 MCP Server 的调研，以下是构建生产级 MCP 爬虫服务器的关键设计模式。

#### 16.2.1 MCP 协议核心概念

MCP（Model Context Protocol）是 Anthropic 推出的标准化协议，让 AI Agent 能够统一发现、调用外部工具。基于 JSON-RPC 2.0，核心三原语：

| 原语 | 作用 | 爬虫场景映射 |
|------|------|------------------|
| **Tools** | Agent 可调用的动作 | `scrape_url`, `extract_data` 等 |
| **Resources** | Agent 可读取的数据源 | 已缓存的页面、站点地图 |
| **Prompts** | 可复用的提示模板 | "提取产品信息"的标准提示 |

两种传输层：
- **stdio**：本地子进程，AI 客户端自动管理，适合本地/私有部署
- **SSE / Streamable HTTP**：远程网络端点，适合 Web/云部署、多 Agent 共享

> 据 Zuplo 2025 年 12 月调查，59% 的 MCP 构建者已迁移至 Streamable HTTP，34% 仍在使用 stdio。趋势是向远程迁移。

#### 16.2.2 传输层选择与部署模式

| 模式 | 适用场景 | 优缺点 | 配置示例 |
|------|----------|--------|----------|
| **stdio** | 本地开发、单 Agent | 简单、零配置；无法远程访问、无法水平扩展 | `{"command": "python", "args": ["-m", "chameleon.mcp_server"]}` |
| **SSE** | Web 部署、HTTP/1.1 | 标准 HTTP 基础设施、负载均衡友好 | `{"url": "http://localhost:8000/mcp"}` |
| **Streamable HTTP** | 现代后端、高并发 | 双向流、低延迟；需 HTTP/2+ | 官方 2025-06-18 规范推荐 |

**本方案推荐**：
- 本地使用：默认 stdio 模式（`mcp.run(transport='stdio')`）
- 生产部署：SSE/Streamable HTTP 模式（挂载到 FastAPI，共享端口和认证）

```python
# 两种模式共存
import mcp.server.sse
from starlette.applications import Starlette
from starlette.routing import Mount

# SSE 模式（可远程访问）
sse = mcp.server.sse.SseServerTransport("/messages")
app = Starlette(routes=[Mount("/mcp", app=sse.get_server())])

# stdio 模式（可本地开发）
# mcp.run(transport='stdio')
```

#### 16.2.4 工具设计最佳实践

从社区实践和 Crawl4AI MCP Server Schema 中提炼：

1. **单一职责**：每个 Tool 只做一件事，降低 Agent 调用时的决策成本
2. **Schema 即契约**：用 JSON Schema 精确定义参数，描述字段用途，帮助模型理解何时调用
3. **description 即文档**：`description` 是 Agent 决策的关键信息源，要写明"何时使用"和"何时不使用"
4. **幂等可重试**：`scrape_url` 对同一 URL 可安全重试，内部缓存避免重复拉取
5. **错误结构化**：返回统一错误对象 `{status, error, suggested_action}`，不抛异常
6. **结果受控**：默认返回 Markdown，必要时返回压缩/截断内容，避免超出 Agent 上下文窗口
7. **支持分页/流式**：大量结果通过 `has_more` + `cursor` 分页返回

**工具 Schema 设计示例**（crawl_site）：

```json
{
  "name": "crawl_site",
  "description": "Crawl multiple pages from a starting URL. Use when the user asks for data from an entire website or section, not a single page.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "url": {"type": "string", "format": "uri", "description": "Starting URL"},
      "max_pages": {"type": "integer", "default": 20, "description": "Maximum pages to crawl"},
      "max_depth": {"type": "integer", "default": 2, "description": "Maximum link depth from start"},
      "strategy": {"type": "string", "enum": ["bfs", "dfs", "adaptive"], "default": "adaptive"},
      "output_format": {"type": "string", "enum": ["markdown", "json"], "default": "markdown"},
      "include_patterns": {"type": "array", "items": {"type": "string"}, "description": "URL path patterns to include"},
      "exclude_patterns": {"type": "array", "items": {"type": "string"}, "description": "URL path patterns to exclude"}
    },
    "required": ["url"]
  }
}
```

#### 16.2.5 安全设计

生产环境 MCP Server 必须考虑的安全性：

| 安全问题 | 建议方案 |
|----------|----------|
| **认证** | MCP 支持 OAuth 2.0；本地 stdio 可信任，远程必须认证 |
| **SSRF 防护** | 严格校验 URL 格式；禁止访问内网 IP（127.0.0.1/10.0.0.0/172.16.0.0/192.168.0.0） |
| **速率限制** | Token Bucket 算法，按 API Key 限流 |
| **URL 白名单** | 可选：限制只能爬取指定域名列表 |
| **审计日志** | 记录每次工具调用：who/when/what/result |
| **输入校验** | `urlparse` 验证 URL 格式；查询长度限制 |

```python
from urllib.parse import urlparse

def validate_url(url: str) -> bool:
    try:
        result = urlparse(url)
        return all([result.scheme in ('http', 'https'), result.netloc])
    except Exception:
        return False

def is_internal_ip(hostname: str) -> bool:
    """SSRF 防护：拒绝内网地址"""
    internal_prefixes = ('127.', '10.', '172.16.', '172.17.', '172.18.',
                         '172.19.', '172.20.', '172.21.', '172.22.',
                         '172.23.', '172.24.', '172.25.', '172.26.',
                         '172.27.', '172.28.', '172.29.', '172.30.',
                         '172.31.', '192.168.', 'localhost')
    return hostname.lower().startswith(internal_prefixes)
```

#### 16.2.7 参考实现代码框架

```python
from mcp.server.fastmcp import FastMCP
from chameleon import Chameleon

mcp = FastMCP("chameleon")
crawler = Chameleon()

@mcp.tool()
async def scrape_url(
    url: str,
    mode: str = "auto",
    output_format: str = "markdown",
    wait_for: str = None,
    proxy_region: str = None
) -> dict:
    """
    Fetch a single web page and return clean markdown or structured data.
    Use this when the user provides a specific URL or asks about a page.
    Do NOT use for: searching the web (use search_web instead).
    """
    return await crawler.scrape(url, mode, output_format, wait_for, proxy_region)

@mcp.tool()
async def extract_data(
    url: str,
    schema: dict,
    strategy: str = "auto"
) -> dict:
    """
    Extract structured data from a webpage based on a JSON Schema.
    Use this when the user asks for specific fields like price, title, date.
    """
    return await crawler.extract(url, schema, strategy)

@mcp.tool()
async def diagnose_site(url: str) -> dict:
    """
    Diagnose a website's anti-bot capabilities and recommend strategy.
    Use this before crawling a new or unfamiliar site.
    """
    return await crawler.diagnose(url)

if __name__ == "__main__":
    mcp.run(transport="stdio")  # 或 "sse"
```
